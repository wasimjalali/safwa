## Top 5 priority fixes (ordered)

1. **Bootstrap the port.** `SUBSCRIBE` from an unbound panel must be accepted and answered with a full snapshot that carries `documentToken` / `sessionEpoch`. Until that works, reset, resync, health identity and feature tokens are dead.
2. **Stop remount count inflation.** Restore occurrence adoption (the v1 fingerprint holder) in `session.js`. Container replacement must retarget anchors, not call `processComment` again.
3. **Make the proxy both reachable and safe.** Set feature availability from a live, unique, re-extracted native row; send/check a per-source revision; refuse twins, already-shown, missing/disabled/duplicate buttons; click the original joined fragment.
4. **Package one product.** The file Chrome actually loads (`manifest.json`) is still v1 while `PANEL_MODE` is sidebar. Either apply `tools/build-manifest.js` v2 (no popup, no `styles.css`, SW + side panel) or do not run `session.js`.
5. **Do not drop records; wire health to ingest.** Publish `folded` + expandable members. Correlate after DOM admit. Stop faking room traffic from the DOM watchdog. A health demotion must stop socket consumption.

## Verdict on production-readiness (one paragraph; state the blockers)

Not production-ready. The matching core, parser and admission *library* tests are green, but the v2 product path cannot be loaded as specified (v1 manifest + sidebar session), cannot complete its port handshake, will double-count on every virtual-scroller remount, never enables a feature button, and drops folded records so an LLM mis-hide is unrecoverable. The live click handler, if it were reached, still lacks sourceRevision / twin / already-shown / original-fragment checks, and the SW forwards a client-supplied `tabId`. Those are blockers for criteria 8–16. Do not put this on a teaching broadcast until 1–5 above are fixed and session-level recycle + proxy tests fail closed.
